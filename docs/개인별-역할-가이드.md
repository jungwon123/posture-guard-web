# 역할별 할 일 가이드 (A to Z)

> 지금 앱은 이미 만들어져 있어요 👉 https://posture-guard-rust.vercel.app (그룹 코드: **9RCSEG**)
> 개발은 정해진 담당이 하고, **여러분은 이 앱을 직접 써보며 다듬고, 왜 좋은지 증명하는 일**을 합니다.
> **가장 먼저**: 무슨 역할이든, 시작 전에 위 링크로 앱을 **5분 이상 직접 써보세요.** 써봐야 뭘 할지 감이 옵니다.

---

## 나는 뭘 보면 되나 (이름 → 볼 곳)

같은 역할이면 **똑같은 일**을 합니다. 역할이 두 개면 두 부분을 다 보세요.

| 이름 | 역할 | 볼 부분 |
|---|---|---|
| 조인성 | 총괄 PM | ① PM |
| 정세아 | 데이터 담당 | ② 데이터 |
| 표수연 | UX 리서처 + QA | ③ UX + ④ QA |
| 조윤준 | UX 리서처 + QA | ③ UX + ④ QA |
| 문권빈 | UX 리서처 + 디자이너 | ③ UX + ⑤ 디자인 |
| 최윤우 | 디자이너 | ⑤ 디자인 |
| 김규빈 | 도메인 리서처 | ⑥ 도메인 리서치 |
| 이민엽 | 도메인 리서처 | ⑥ 도메인 리서치 |

> 같은 역할끼리는 **각자 따로, 같은 방법으로** 하면 됩니다. 예를 들어 UX 리서처 3명은 각자 다른 사람을 대상으로 같은 테스트를 하면, 결과가 3배로 모여서 더 정확해져요.

## ① PM — 조인성

**이 역할은?** 팀이 굴러가게 하는 사람. 누가·무엇을·언제까지 하는지 챙깁니다.

**할 일 A to Z**

1. **할 일 표를 만든다.** 종이나 노션에 세 칸짜리 표를 그린다 — `누가 / 무엇을 / 언제까지`. 이 가이드에 나온 각자의 "내는 것"을 그대로 옮겨 적으면 시작 끝.
2. **매주 한 번 회의를 연다.** 시간은 30분. 안건은 항상 **3개**로 고정:
   - (1) 지난주에 각자 낸 것 보기
   - (2) 이번 주에 할 것 정하기
   - (3) 막힌 것 이야기하기
3. **산출물은 회의 전날까지** 팀 폴더(카톡·노션 등)에 올리라고 미리 공지한다. 회의에서 처음 보여주면 읽느라 시간이 다 간다.
4. **회의록을 쓴다.** 길게 말고 "누가 무엇을 언제까지 하기로 했다" 3줄이면 충분.
5. **막힌 것·질문을 모아** 개발 담당에게 **한 번에** 전달한다. (한 명씩 따로 물으면 개발자가 정신없음)

**내는 것**: 할 일 표, 매주 회의록
**조심할 것**: 혼자 다 하려 하지 말 것. PM은 "하는 사람"이 아니라 "챙기는 사람".

## ② 데이터 담당 — 정세아

**이 역할은?** "이 앱이 자세를 얼마나 정확하게 맞히나"를 **숫자로** 밝히는 사람. (발표 때 제일 강력한 자료가 됩니다.)

**할 일 A to Z** — 어렵지 않아요. 종이와 앱만 있으면 됩니다.

1. 앱을 열고 **기준 등록**을 한다 (바르게 앉아서 "기준 등록(5초)" 누르기).
2. **종이에 표를 그린다**: 두 칸 — `오탐 / 미탐`.
   - **오탐** = 나는 바르게 앉아 있는데 앱이 "나쁜 자세"라고 잘못 알린 것 ❌
   - **미탐** = 나는 진짜 구부정한데 앱이 못 잡고 그냥 넘어간 것 ❌
3. **평소처럼 30분 공부한다.** 그러면서 앱을 곁눈질하며, 위 두 경우가 생길 때마다 종이에 **바를 정(正)자로 개수를 센다.**
4. 30분 뒤 세어본다 — 오탐 몇 번, 미탐 몇 번.
5. **팀원 전원에게 똑같이 시킨다.** "30분 써보고 오탐·미탐 세서 알려줘"라고 부탁 → 8명치를 걷는다.
6. **정확도 표로 정리한다**: 이름별 오탐·미탐 개수. 오탐이 유독 많으면 "알림이 너무 예민하다", 미탐이 많으면 "너무 둔하다"는 결론이 나온다.
7. 그 결과를 **개발 담당에게 전달**한다. 개발자가 민감도를 조절한 뒤, **다시 한 번 같은 방법으로 재보면** "전보다 오탐이 줄었다"를 숫자로 보여줄 수 있다 → 이게 발표의 핵심 자료.

**내는 것**: 오탐·미탐 정확도 표 (팀원 8명치), 전/후 비교
**조심할 것**: 컴퓨터 코딩은 필요 없어요. 그냥 쓰면서 종이에 세면 됩니다.

## ③ UX 리서처 — 표수연 · 조윤준 · 문권빈 (셋 다 같은 일)

**이 역할은?** "처음 보는 사람이 설명 없이도 이 앱을 잘 쓰나?"를 **직접 지켜보며** 알아내는 사람.

**할 일 A to Z** — 이걸 "사용성 테스트"라고 해요. 설문(질문지)이 아니라, **한 명을 옆에서 지켜보는** 것입니다.

1. **테스트할 사람 1~2명을 구한다.** 앱을 처음 보는 사람이면 됨 — 친구, 가족, 팀원끼리도 OK. (많이 필요 없어요, 1~2명이면 충분.)
2. 그 사람에게 폰이나 노트북으로 **링크만 열어준다.** 그리고 **미션 한 줄만** 준다:
   > "이 앱으로 자세를 등록하고, 자세가 나쁠 때 알림을 받아보세요."
3. **⚠️ 절대 설명하거나 도와주지 않는다.** 이게 제일 중요! 막혀서 헤매도 조용히 지켜본다. (도와주면 진짜 문제가 안 보임.)
4. **옆에서 종이에 적는다** — 이런 걸 관찰:
   - 어디서 **멈칫**했나? (뭘 눌러야 할지 몰라 헤맨 곳)
   - 뭘 **못 찾았나**? (버튼이 어디 있는지 모른 곳)
   - 무슨 **말**을 했나? ("이게 뭐지?", "어 이거 어떻게 해?")
   - 처음부터 끝까지 **몇 분** 걸렸나?
5. 다 하고 나서 **딱 두 개만 물어본다**: "제일 헷갈린 게 뭐였어?" / "또 쓸 것 같아?"
6. **"막힌 지점 3개"로 정리한다.** 예: "① 기준 등록 버튼을 못 찾음 ② 알림이 언제 오는지 모름 ③ 탭이 5개라 헷갈림"

**내는 것**: 관찰 기록 (테스트한 사람 수만큼) + 막힌 지점 TOP 3
**조심할 것**: 설명 금지! "이거 눌러" 한마디만 해도 테스트가 망가집니다. 벙어리처럼 지켜보세요.

## ④ QA — 표수연 · 조윤준 (둘 다 같은 일)

**이 역할은?** 앱의 기능이 **안 망가졌는지 하나하나 확인**하는 사람. (버그 잡는 사람)

**할 일 A to Z**

1. **체크리스트를 만든다.** "이렇게 하면 → 이렇게 되어야 함" 목록. 아래를 그대로 써도 됩니다:

   | 이렇게 하면 | 이렇게 되어야 함 |
   |---|---|
   | 카메라 시작 | 화면에 내 모습이 나온다 |
   | 기준 등록(5초) | GOOD이 뜨고 점수가 나온다 |
   | 나쁜 자세로 앉기 | 몇 초 뒤 알림이 온다 |
   | 카메라 켜기 | 출석 도장이 찍힌다 |
   | 상점에서 스킨 구매 | 포인트가 줄고 "보유 중"이 된다 |
   | 캐릭터 페이지에서 스킨 바꾸기 | 캐릭터 모습이 바뀐다 |
   | 그룹 만들기 | 6자리 코드가 나온다 |
   | 친구를 콕 찌르기 | 친구 폰에 알림이 온다 |

2. **하나씩 실제로 해본다.** 되면 ✅, 안 되거나 이상하면 ✍️ 표시.
3. 안 되는 것 = **버그**. 이렇게 적는다 (버그 리포트):
   - **무엇을 했나**: "그룹 만들기 버튼을 눌렀다"
   - **뭐가 나와야 하나**: "6자리 코드가 나와야 한다"
   - **실제로 뭐가 나왔나**: "아무 일도 안 일어났다"
   - **스크린샷**: 그 화면 캡처
4. 버그를 **개발 담당에게 전달** → 고쳤다고 하면 **다시 확인**해서 진짜 고쳐졌는지 본다.
5. **핸드폰·컴퓨터 여러 기기**에서 해본다 (아이폰·안드로이드·노트북). 기기마다 다를 수 있음.

> 표수연·조윤준 둘 다 같은 체크리스트로 하되, 서로 다른 기기로 하면 좋아요. 콕 찌르기는 **둘이 서로 그룹에 들어가서** 주고받아 보면 됩니다.

**내는 것**: 체크리스트(✅/✍️ 표시된 것), 버그 리포트
**조심할 것**: "되겠지" 하고 넘기지 말고 진짜로 눌러볼 것.

## ⑤ 디자인 — 최윤우 · 문권빈 (둘 다 같은 일)

**이 역할은?** 화면이 **더 예쁘고 쓰기 편하게** 바뀌도록 그림으로 제안하는 사람.

**할 일 A to Z**

1. **지금 앱 화면을 캡처한다.** 5개 탭(홈·그룹·상점·캐릭터·로그인)을 각각 스크린샷. (폰은 전원+음량 버튼, 컴퓨터는 캡처 도구)
2. 캡처한 그림 위에 **직접 표시한다** — "여기 이렇게 바꾸면 좋겠다". 그림판·굿노트·심지어 종이에 인쇄해서 펜으로 그려도 됩니다.
3. **⚠️ 규칙: "예쁘게"가 아니라 "구체적으로".** 색·크기·위치를 정확히.
   - ❌ "버튼 예쁘게" → ✅ "시작 버튼을 화면 맨 아래, 지금보다 2배 크게, 초록색으로"
4. (원하면) **캐릭터 스킨이나 상점 아이템**을 새로 그린다. 정사각형 그림으로.
5. **색·글꼴 한 장**으로 정리한다 — 강조색 1개, 상태색 3개(좋음 초록 / 나쁨 빨강 / 자리비움 회색), 글꼴 1개.

> 최윤우·문권빈 둘 다 각자 시안을 만든 뒤, **둘을 비교해서 좋은 걸 고르거나 합치면** 됩니다.

**내는 것**: 화면 개선 시안 (5페이지), (선택) 캐릭터·아이콘 그림, 색·글꼴 정리 1장
**조심할 것**: 처음부터 완벽하게 그리려 하지 말 것. "이 부분이 불편하니 이렇게" 한 곳씩이면 충분.

## ⑥ 도메인 리서치 — 김규빈 · 이민엽 (둘 다 같은 일)

**이 역할은?** "거북목이 진짜 문제다 + 우리 앱이 남들과 다르다"를 **자료로 뒷받침**하는 사람. (설문은 안 해요. 이미 세상에 있는 자료를 찾는 겁니다.)

**할 일 A to Z** — 두 가지를 찾습니다.

**(가) 거북목이 문제라는 근거 찾기**
1. 검색창에 이렇게 쳐본다: `청소년 거북목`, `거북목 증후군 통계`, `스마트폰 목 건강`, `text neck`
2. **믿을 만한 자료**를 고른다. 순위: 공공기관(건강보험공단·질병관리청)·병원·논문 요약 > 뉴스 기사 > 개인 블로그(피하기). **어디서 봤는지 링크를 꼭 적는다.**
3. **3개를 정리한다**: 각각 `무슨 내용인지 / 어디서 봤는지(링크) / 왜 중요한지` 한 줄씩.

**(나) 비슷한 서비스 찾기**
1. 검색: `자세 교정 앱`, `posture app`, `webcam posture`, `거북목 감지`
2. **3개를 골라** 각각 확인: `어떻게 감지하나(카메라? 센서?) / 영상이 어디로 가나(서버로? 기기 안?) / 우리와 뭐가 다른가`
3. **표로 정리한다** (앱 이름 / 방식 / 프라이버시 / 우리와의 차이).

> 김규빈·이민엽 둘 다 같은 걸 찾되, 자료가 겹치면 **합쳐서 더 튼튼하게** 만들면 됩니다. 서로 다른 검색어로 찾으면 더 다양하게 모여요.

**내는 것**: 거북목 근거 3개(링크 포함), 비슷한 서비스 비교표 3개
**조심할 것**: 출처(링크) 없는 자료는 발표 때 못 씁니다. 반드시 어디서 봤는지 적기.

## 이번 주에 당장 시작할 것 (한 줄씩)

- **조인성**: 할 일 표 만들고 첫 회의 날짜 잡기
- **정세아**: 종이에 오탐·미탐 표 그리고 30분 써보기 + 팀원들에게 부탁 공지
- **표수연**: 친구 1명에게 설명 없이 앱 시켜보고 관찰 (+ QA 체크리스트 한 번 돌리기)
- **조윤준**: 표수연과 서로 그룹 들어가 콕 주고받아 보기 (+ 친구 1명 관찰)
- **문권빈**: 친구 1명 관찰 (+ 5페이지 캡처해서 어색한 곳 표시)
- **최윤우**: 5페이지 캡처해서 "이렇게 바꾸자" 표시 시작
- **김규빈**: 거북목 근거 자료 3개 검색해서 링크 모으기
- **이민엽**: 비슷한 자세 앱 3개 찾아서 비교표 시작

> 다시 강조: 뭘 하든 **앱을 먼저 5분 써보세요** (링크 + 그룹 코드 9RCSEG). 안 써보고 하면 헛돕니다.
