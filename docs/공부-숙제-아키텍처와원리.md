# 숙제 — 우리 시스템은 어떻게 만들어졌고, 자세를 어떻게 판단할까?

> 우리가 만든 척추요정이 **어떤 구조로 돌아가고**, **무슨 원리로 자세를 판단하는지** 공부하는 숙제예요.
> 코딩을 몰라도 됩니다. 아래 키워드를 검색해 이해하고, 각 질문에 **자기 말로** 답하면 돼요.

## 어떻게 공부하나요

1. 각 주제의 **키워드**를 검색한다 (유튜브 "○○ 쉽게", 나무위키, 블로그 등)
2. "우리 앱에선"을 읽고 **우리 앱의 어디에 해당하는지** 연결해 본다
3. **확인 질문**에 자기 말로 3~4줄 답을 쓴다 (베껴 쓰지 말고 이해한 대로)

⭐ = 꼭 하기 / 🔥 = 더 궁금한 사람용(심화)

체험하면서 하면 훨씬 잘 이해돼요 👉 https://posture-guard-rust.vercel.app (그룹 코드 9RCSEG)

# Part A. 시스템 아키텍처 (어떻게 만들어졌나)

## A-1. ⭐ 프론트엔드 vs 백엔드

- **키워드**: 프론트엔드, 백엔드, 클라이언트-서버, API
- **이게 뭐냐**: 앱은 보통 "화면 쪽(프론트엔드)"과 "서버 쪽(백엔드)"으로 나뉜다. 화면은 사용자가 보고 만지는 부분, 서버는 뒤에서 데이터를 저장·처리하는 부분.
- **우리 앱에선**: 카메라 화면·점수·캐릭터는 전부 **프론트엔드**(내 기기)에서, 그룹 랭킹만 **백엔드**(서버)에서 담당한다.
- **확인 질문**: 우리 앱에서 프론트엔드가 하는 일과 백엔드가 하는 일을 하나씩 예로 들어 설명해 보세요.

## A-2. ⭐ 웹앱과 PWA (설치 없이 앱처럼)

- **키워드**: 웹앱, PWA(프로그레시브 웹 앱), 서비스워커, 홈 화면에 추가
- **이게 뭐냐**: 앱스토어에서 받지 않고 **웹사이트를 앱처럼** 쓰게 해주는 기술. 홈 화면에 추가하면 아이콘도 생기고 알림도 온다.
- **우리 앱에선**: 링크만 열면 바로 쓰이고, "홈 화면에 추가"하면 설치한 앱처럼 동작한다.
- **확인 질문**: 앱스토어 앱과 PWA는 뭐가 다를까요? PWA의 장점 2가지를 써보세요.

## A-3. ⭐ 기기 안에서 도는 AI (온디바이스 AI)

- **키워드**: 온디바이스 AI, 엣지 컴퓨팅, MediaPipe, WebAssembly(WASM)
- **이게 뭐냐**: AI를 인터넷 너머 서버가 아니라 **내 기기 안에서** 직접 돌리는 것. 우리는 구글의 **MediaPipe**라는 AI를 브라우저 안에서 돌린다.
- **우리 앱에선**: 카메라 영상을 서버로 보내지 않고, 브라우저 안 AI가 바로 분석하고 버린다. 이게 우리 **개인정보 보호**의 핵심.
- **확인 질문**: AI를 서버가 아니라 내 기기에서 돌리면, 개인정보(카메라 영상)에 왜 더 안전할까요?

## A-4. ⭐ 서버·클라우드·데이터베이스

- **키워드**: 클라우드, 서버, 가상 머신(VM), 데이터베이스, SQL, 서버리스
- **이게 뭐냐**: "클라우드"는 남의 컴퓨터(구글·아마존 등)를 빌려 쓰는 것. 그 위에서 프로그램을 돌리고, **데이터베이스**에 정보를 저장한다.
- **우리 앱에선**: 구글 클라우드(GCP)의 가상 컴퓨터 한 대를 빌려 서버를 돌리고, **PostgreSQL**이라는 데이터베이스에 그룹·랭킹 정보를 저장한다. (처음엔 "서버리스"로 만들었다가 직접 관리하는 VM으로 옮김)
- **확인 질문**: 데이터베이스는 왜 필요할까요? 우리 앱에서 데이터베이스에 저장되는 정보는 무엇일까요?
- 🔥 **심화**: "서버리스"와 "가상 머신(VM)"의 차이를 찾아보고, 각각 언제 쓰면 좋을지 써보세요.

## A-5. ⭐ 안전하게 연결하기 (HTTPS)

- **키워드**: HTTP / HTTPS, SSL·TLS 인증서, 개인정보 보호
- **이게 뭐냐**: 웹사이트 주소 앞의 **https**는 "암호화된 안전한 연결"이라는 뜻. 카메라·알림 같은 민감한 기능은 https에서만 쓸 수 있다.
- **우리 앱에선**: 카메라를 쓰려면 https가 꼭 필요해서, 서버에 자동으로 보안 인증서를 붙였다.
- **확인 질문**: 왜 카메라를 쓰는 웹사이트는 http가 아니라 https여야 할까요?

## A-6. 🔥 서버 남용 막기 (심화)

- **키워드**: 레이트 리밋(요청 제한), 캐시(cache), 트래픽
- **이게 뭐냐**: 누구나 쓰는 서비스는 나쁜 사람이 마구 요청을 보내 서버를 망가뜨릴 수 있다. 그래서 "1분에 몇 번까지만" 같은 **제한**을 건다. 또 같은 요청은 잠깐 저장해뒀다(캐시) 재사용해 서버 부담을 줄인다.
- **우리 앱에선**: 그룹 만들기·콕 찌르기에 횟수 제한을 걸었고, 랭킹은 30초간 캐시해서 서버를 아낀다.
- **확인 질문**: 요청 제한(레이트 리밋)이 없으면 어떤 문제가 생길 수 있을까요?

## A-7. ⭐ 전체 그림 그려보기

- **할 일**: 우리 시스템이 어떻게 연결되는지 **화살표 그림**으로 그려보세요. (아래 힌트 참고)

```
[내 카메라] → [브라우저 안 AI(MediaPipe)] → [자세 판단·점수·알림]   ← 여기까지 전부 내 기기
                                                      │
                                          (그룹 랭킹에 쓸 숫자만)
                                                      ▼
                                            [서버(GCP) + 데이터베이스]
```

- **확인 질문**: 이 그림에서 **서버로 나가는 데이터는 무엇뿐**인가요? 카메라 영상은 왜 서버로 안 갈까요?

# Part B. 자세를 어떻게 판단할까 (핵심 원리)

## B-1. ⭐ 포즈 추정 (컴퓨터가 몸을 인식하는 법)

- **키워드**: 포즈 추정(pose estimation), 랜드마크·키포인트, 컴퓨터 비전
- **이게 뭐냐**: AI가 사진·영상에서 사람 몸의 **주요 지점(관절·눈·코 등)의 위치**를 찾아내는 기술. 그 점 하나하나를 랜드마크(landmark)라고 한다.
- **우리 앱에선**: MediaPipe가 화면에서 **코·양쪽 귀·양쪽 어깨** 위치를 찾는다. (앱의 오른쪽 TRACKING 화면에서 점·선으로 볼 수 있어요)
- **확인 질문**: 우리 앱이 자세를 판단하려고 몸에서 찾는 5개 지점은 무엇인가요? 왜 이 지점들일까요?

## B-2. ⭐ 위치를 "신호"로 바꾸기 (특징 추출·정규화)

- **키워드**: 특징(feature), 정규화(normalization), 비율
- **이게 뭐냐**: 찾은 점들의 위치를 그대로 쓰지 않고, **의미 있는 값**으로 바꾼다. 예를 들어 "코가 귀보다 얼마나 아래 있나"처럼. 이때 절대 거리 대신 **비율**을 써서 카메라와의 거리가 달라도 괜찮게 만든다(정규화).
- **우리 앱에선**: 5개 점으로 거북목 신호 4가지(머리가 앞으로/고개 숙임/머리 하강/어깨 말림)를 **비율로** 계산한다.
- **확인 질문**: 만약 그냥 "코와 어깨 사이 거리(cm)"를 쓰면 왜 문제가 될까요? 비율을 쓰면 뭐가 좋아질까요?

## B-3. ⭐ 나만의 기준 만들기 (캘리브레이션·통계)

- **키워드**: 캘리브레이션(보정), 평균(mean), 표준편차(standard deviation), 기준선(baseline)
- **이게 뭐냐**: 사람마다 체형이 달라서 "모두에게 맞는 바른 자세"는 없다. 그래서 처음에 **내 바른 자세를 잠깐 재서 평균**을 구하고, 얼마나 흔들리는지(표준편차)도 잰다. 이게 내 기준선.
- **우리 앱에선**: "기준 등록 5초" 동안 내 바른 자세의 **평균과 표준편차**를 저장한다. 이후 모든 판단은 이 기준과 비교.
- **확인 질문**: "평균"과 "표준편차"가 각각 무슨 뜻인지 찾아보고, 왜 우리가 사람마다 기준을 따로 만드는지 설명해 보세요.

## B-4. ⭐ 점수 매기기 (기준에서 얼마나 벗어났나)

- **키워드**: 표준점수(z-score), 편차, 가중치(weight)
- **이게 뭐냐**: 지금 값이 내 평소 기준에서 **몇 배나 벗어났는지**를 숫자로 만든다(z-score). 조금 벗어난 건 봐주고, 많이 벗어날수록 점수를 깎는다. 신호마다 중요도(가중치)가 다르다.
- **우리 앱에선**: 4개 신호가 나쁜 방향으로 얼마나 벗어났는지 재서, 가중치대로 합쳐 **0~100점**을 만든다.
- **확인 질문**: "내 평소보다 유난히 많이 벗어났다"를 숫자로 표현하는 게 왜 유용할까요? (힌트: 사람마다 흔들리는 정도가 다름)
- 🔥 **심화**: z-score(표준점수)가 무엇인지 찾아보고, 왜 그냥 "차이"가 아니라 "표준편차로 나눈 값"을 쓰는지 생각해 보세요.

## B-5. ⭐ 순간이 아니라 "지속"을 보기 (상태 판단)

- **키워드**: 상태 머신(state machine), 임계값(threshold), 히스테리시스, 디바운스, 노이즈
- **이게 뭐냐**: 점수는 계속 조금씩 출렁인다(노이즈). 이걸 그대로 알림으로 쓰면 시도 때도 없이 울린다. 그래서 **"몇 점 아래로 몇 초 이상 지속돼야" 나쁜 자세로 판단**한다. 또 들어갈 때(60점)와 나올 때(75점) 기준을 다르게 둬서 경계에서 왔다 갔다 하지 않게 한다(히스테리시스).
- **우리 앱에선**: 점수가 낮아도 **잠깐이면 넘어가고**, 계속 유지될 때만 "나쁜 자세"로 바꿔 알림을 준다.
- **확인 질문**: "잠깐 물건 주우려고 숙인 것"과 "계속 구부정하게 있는 것"을 우리 앱은 어떻게 구별할까요?
- 🔥 **심화**: 히스테리시스와 디바운스가 각각 무엇인지 찾아보고, 이게 없으면 알림이 어떻게 될지 상상해 써보세요.

## B-6. 🔥 우리는 왜 "딥러닝"을 안 썼을까 (심화)

- **키워드**: 규칙 기반 vs 머신러닝, 딥러닝, 학습 데이터
- **이게 뭐냐**: 요즘 AI(딥러닝)는 수많은 데이터를 학습해서 판단한다. 하지만 우리는 자세 판단을 **학습 없이 통계와 규칙**으로 했다 (몸 위치 → 계산 → 내 기준과 비교).
- **우리 앱에선**: "많은 사람의 나쁜 자세 데이터"를 모으지 않고도, 각자의 기준으로 판단해서 학습 데이터가 필요 없다.
- **확인 질문**: 우리처럼 규칙·통계로 하는 방법과 딥러닝으로 배우는 방법, 각각의 장단점을 한 가지씩 써보세요.
