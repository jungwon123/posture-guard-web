# Posture Guard 기능 아이디어 브레인스토밍 가이드

> 대상: 고1 팀원 8명 (도메인 지식 없음 전제)
> 도구: Excalidraw (아래 "구역"을 보드에 미리 그려두고 시작)
> 소요: 약 60분 · 진행: PM(또는 개발자)

---

## 보드 배치 (미리 그려둘 것)

```
┌─────────────┬───────────────────────────┬─────────────┐
│ ① 오늘의 목표 │ ③ 아이디어 벽 (스티키 존)     │ ④ 투표 존    │
│ ② 규칙 4개   │   질문카드 A  B  C  D       │             │
├─────────────┴───────────────────────────┴─────────────┤
│ ⑤ 구체화 카드 3장 (템플릿)          │ ⑥ 주차장(나중에) │
└───────────────────────────────────────────────────────┘
```

---

## 구역 ① 오늘의 목표 (보드에 크게 적기)

> **"자세 알리미(Posture Guard)에 어떤 기능이 더 있으면 좋을지, 아이디어를 최대한 많이 꺼낸 다음, 3개를 골라 구체화한다."**

- 지금 있는 것: 카메라로 거북목 감지 → 점수 → 나쁜 자세 지속되면 알림
- 오늘 찾는 것: "이게 있으면 **계속 쓰고 싶어진다**" 싶은 기능

## 구역 ② 규칙 4개 (보드에 붙여두고 진행자가 소리 내어 읽기)

1. **비판 금지** — "그건 안 될걸?"은 오늘 금지어. 판단은 투표 때 한다.
2. **질보다 양** — 이상한 아이디어 10개가 좋은 아이디어 1개보다 낫다.
3. **얹기 환영** — 남의 스티키에 "+이러면 더 좋겠다"를 붙이는 건 최고의 기여.
4. **말 대신 손** — 떠오르면 일단 스티키에 쓴다. 한 장에 아이디어 하나.

---

## 진행 순서 (60분)

| 시간 | 하는 일 |
|---|---|
| 0~10분 | **데모 보기**: 개발자가 실제 프로그램 시연 (일부러 거북목 해서 알림 받는 것까지) |
| 10~15분 | 규칙 읽기 + 스티키 쓰는 법 안내 |
| 15~35분 | **조용히 쓰기**: 말하지 않고 각자 스티키 작성 (질문카드 A→B→C→D 순서로 5분씩) |
| 35~45분 | **돌아가며 소개**: 자기 스티키 중 베스트 2개만 30초씩 소개, 비슷한 것끼리 묶기 |
| 45~50분 | **투표**: 1인당 ⭐ 3개 (자기 것에 몰빵 금지, 최대 1개만) |
| 50~60분 | 상위 3개를 **구체화 카드**로 옮겨 다같이 채우기 |

> 왜 "조용히 쓰기"부터? 말로 시작하면 목소리 큰 2~3명의 아이디어만 남는다. 8명 전원의 아이디어를 꺼내는 게 목적.

---

## 구역 ③ 질문카드 (아이디어 벽에 4장 붙여두기)

막막하면 아이디어가 안 나온다. 아래 질문에 답하는 방식으로 쓰게 한다.

**카드 A — 알림에 대해** 🔔
- 공부 중에 알림이 오면 솔직히 어떤 기분일까?
- 짜증 안 나는 알림은 어떤 모습일까? (소리? 그림? 캐릭터? 진동?)
- 반대로 "칭찬"은 언제 어떻게 받으면 기분 좋을까?

**카드 B — 계속 쓰게 만들기** 🔁
- 3일 쓰고 지울 것 같은 이유는 뭘까? 그걸 막으려면?
- 게임 요소가 있다면? (연속 기록, 레벨, 포인트, 캐릭터 키우기…)
- 하루가 끝났을 때 뭘 보여주면 "오늘 잘했다" 느낌이 들까?

**카드 C — 같이 쓰기** 👥
- 친구랑 같이 쓴다면 뭘 하고 싶을까? (대결? 랭킹? 서로 알림?)
- 부모님·선생님이 이걸 본다면 어떤 기능을 원할까?
- 우리 반 전체가 쓴다면 무슨 일이 생길까?

**카드 D — 엉뚱한 상상** 🚀
- 돈·기술 제한이 전혀 없다면 뭘 만들까?
- 이 프로그램이 자세 말고 다른 것도 지켜준다면? (눈 깜빡임, 물 마시기, 화면과의 거리…)
- 스마트폰/태블릿이라면 뭐가 달라질까?

## 스티키 쓰는 법 (예시를 보드에 1장 붙여두기)

```
┌────────────────────────┐
│ [B] 연속 3일 좋은 자세면    │   ← 카드 기호 + 아이디어 한 문장
│ 캐릭터가 진화한다          │
│                (지은)     │   ← 이름
└────────────────────────┘
```

- 한 장 = 아이디어 하나. 문장은 짧게. 그림으로 그려도 OK.
- 개수 목표: **1인당 최소 6장** (카드당 1~2장꼴). 많을수록 좋다.

---

## 구역 ④ 투표 존

- 묶인 아이디어 그룹들을 이 구역으로 옮기고, 각자 ⭐를 3개 붙인다.
- 투표 기준 (보드에 적어두기): **"내가 진짜 쓸 것 같다"** — 멋있어 보이는 것 말고.
- 동점이면 개발자가 "만들기 쉬운 쪽"에 손을 들어준다 (현실 반영).

## 구역 ⑤ 구체화 카드 (빈 템플릿 3장 미리 그려두기)

투표 상위 3개를 이 템플릿으로 채운다. **여기까지 채워져야 "기능 아이디어"가 된다.**

```
┌─────────────────────────────────────────┐
│ 기능 이름:                                │
│ 한 문장 설명: "____가 ____할 때 ____해준다"  │
│ 누가 언제 쓰나:                            │
│ 화면에 뭐가 보이나: (그림으로 그려도 됨)       │
│ 이게 있으면 뭐가 달라지나:                   │
│ 걱정되는 점 하나:                           │
└─────────────────────────────────────────┘
```

## 구역 ⑥ 주차장 🅿️

- 좋은데 오늘 주제(기능)가 아닌 것들 — 이름, 디자인, 발표 아이디어 등은 여기에 붙인다. 버리는 게 아니라 **나중에 쓰려고 보관**하는 것.

---

## 끝나고 할 일 (역할 연결)

| 누가 | 무엇을 |
|---|---|
| PM | 구체화 카드 3장을 백로그에 등록, 다음 회의 안건으로 |
| UX 리서처 | 상위 아이디어에 대해 "진짜 쓸까?" 미니 인터뷰 2~3명 |
| 디자이너 | 구체화 카드의 "화면에 뭐가 보이나"를 시안으로 |
| 테크니컬 라이터 | 보드 전체 스크린샷 + 오늘 결과 1페이지 정리 |
| 개발자 | 3개 기능의 난이도(상/중/하)만 다음 회의까지 판정 |

## 진행자 팁

- 조용히 쓰기 시간에 **진행자도 같이 쓴다** (감시하는 분위기 방지).
- 5분마다 "다음 카드로 넘어갈게요"라고 환기. 타이머를 보드에 띄워두면 좋다.
- 스티키가 안 나오는 친구에겐 질문카드를 소리 내어 읽어주기 — 비난 말고 질문으로.
- 데모가 제일 중요하다. **실물을 봐야 아이디어가 나온다.** 데모 없이 시작하지 말 것.
