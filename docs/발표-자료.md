## 1. 우리 서비스 개요

**척추요정 — "자세까지 지켜주는 열품타"**
웹캠으로 거북목·굽은 등을 실시간 감지하면서 공부 시간을 재는 웹앱(PWA). 설치 없이 링크로 열고, 홈 화면에 추가하면 앱처럼 쓴다.

- **문제**: 고등학생은 하루 10시간 가까이 앉아서 공부한다. 공부 시간을 재는 앱(열품타)은 많지만, 그 시간 동안 **몸이 망가지는 건 아무도 안 봐준다**. 거북목은 한 번 생기면 되돌리기 어렵다.
- **해법**: 공부 타이머에 자세 감지를 결합 — 앉아 있는 동안만 시간이 쌓이고(착석 기반 순공시간), 자세가 무너지면 요정이 바로 알려준다.
- **차별점 한 줄**: 열품타의 순공시간은 "폰을 안 봤다"는 간접 증거지만, 우리는 **카메라로 실제 앉아 공부한 시간**을 잰다. 그리고 "수학 할 때 유독 자세가 무너져요" 같은 리포트는 **세상에서 우리만 만들 수 있다.**
- **프라이버시 원칙(중요)**: 모든 영상 분석은 **내 기기 안에서만** 돈다(온디바이스 AI). 서버로 가는 건 "오늘 몇 분, 바른 자세 몇 %" 같은 **숫자와 닉네임뿐** — 영상·사진은 어디에도 저장·전송되지 않는다.
- **팀**: 9인 (개발 1 + 기획·디자인·QC 8) — QC 실사용 테스트, 디자인 컨셉, 기능 기획을 팀이 분담.

**[말하기]** "공부 시간을 재주는 앱은 많습니다. 그런데 그 10시간 동안 여러분의 목은 누가 지켜주나요? 저희는 타이머에 자세를 붙였습니다."

## 2. 핵심 기능 — 딱 2가지에 집중

> 발표는 이 2개만 깊게. 나머지(타이머·요정 스킨·통계·계정)는 시연 화면에 자연스럽게 보이는 걸로 충분.

### 기능 ① 공부하다 자세가 무너지면, 바로 알림

- 웹캠이 상반신을 초당 10회 분석 → 거북목·고개 숙임·굽은 등·기운 어깨를 감지.
- 시작할 때 5초 '바른 자세 등록' → **내 기준**에서 벗어나면 요정이 아파하며 알려줌 (목/등/골반 — 아픈 부위별로 다르게).
- 잠깐 흐트러진 건 봐주고, 계속 방치하면 알림이 단계적으로 세짐.
- ★시연: 공부 시작 → 기준 등록 → 일부러 거북목 → 요정 반응 + 알림.

**[핵심 기술 ①-A] AI는 점만 찍는다, 판단은 우리 수학 (MediaPipe)**
구글이 공개한 온디바이스 AI가 웹캠 화면에서 몸 관절 33개 + 얼굴 468개 점의 **좌표**를 초당 10번 찾아준다. AI의 역할은 여기까지 — 그 좌표들로 "거북목인가?"를 판정하는 계산(각도·기울기·비율)은 전부 우리가 직접 설계했다.
**[말하기]** "AI는 몸에 점을 찍어줄 뿐입니다. 그 점들의 좌표로 거북목을 판단하는 수학은 저희가 직접 만들었습니다."

**[핵심 기술 ①-B] 개인 맞춤 기준 (캘리브레이션)**
사람마다 체형·앉은 키·카메라 위치가 달라서 '정답 자세' 하나로는 판정 불가. 그래서 시작할 때 5초간 그 사람의 바른 자세를 기록해 **나만의 기준값**을 만들고, 이후에는 기준 대비 얼마나 벗어났는지(편차)만 본다. 비유: 체중계 **영점 조절**.

**[핵심 기술 ①-C] 눈동자로 거리를 잰다 (홍채 닮음비)**
사람 홍채(눈동자 테두리) 실제 지름은 누구나 약 11.7mm로 거의 같다. 얼굴이 카메라에 가까워지면 화면 속 홍채가 커진다 → 수학 시간에 배운 **닮음비**로 얼굴-카메라 거리를 역산할 수 있다. 거북목은 "몸은 그대로인데 머리만 앞으로 나오는" 자세라서, **몸은 안 가까워졌는데 얼굴만 가까워진 순간**을 잡아내면 된다.
**[말하기]** "특별한 센서 없이, 웹캠과 중학교 수학 닮음비만으로 거리를 잽니다."

**[핵심 기술 ①-D] 신호 8종 교차 판정 + 떨림 필터**
한 가지 신호만 보면 오판한다(잠깐 고개 숙여 필기한 것 vs 진짜 거북목). 그래서 거북목·고개 숙임·머리 높이·어깨 기울기·어깨 말림·좌우 쏠림·갸웃·턱괴기 **8개 신호를 함께** 보고 가장 심한 부위를 짚는다. 임계값은 선행 학술논문(JIIBC 2024)과 대조해 설계. 측정값의 잔떨림은 필터(One-Euro)로 걸러 오탐을 줄였다.

**[핵심 기술 ①-E] 영상은 내 기기 밖으로 안 나간다 (온디바이스)**
위의 모든 분석이 **내 브라우저 안에서만** 돈다. 영상·사진은 인터넷으로 전송·저장되지 않고, 서버로 가는 건 "오늘 몇 분, 바른 자세 몇 %" 같은 숫자와 닉네임뿐.

### 기능 ② 함께 공부 — 독서실처럼, 서로 보이게

- 그룹 코드로 입장 → 친구들의 실시간 접속 상태 + 주간 랭킹 명예의 전당.
- **실시간 카메라 그리드**: 반 친구들이 서로의 공부 모습을 보며 공부 (옵트인 — 본인이 켜야만 보임).
- **콕 찌르기**: 조는 친구에게 전용 알림음 + 진동.
- ★시연: 폰 2대로 그리드 열고 콕 찌르기.

**[핵심 기술 ②-A] WebRTC — 줌이 쓰는 그 기술**
줌·구글미트가 쓰는 웹 표준 기술로, 브라우저끼리 실시간 영상을 주고받는다. 문제는 "여러 명"일 때 — 여기서 우리의 3단계 도전이 시작된다.

**[핵심 기술 ②-B] 1단계: 직접 연결(P2P)을 직접 구현 → 한계를 실측**
처음엔 서버 없이 브라우저끼리 직접 연결하는 방식을 밑바닥부터 구현했다. 그런데 4명이 모이면 내 영상을 3명에게 **각각 따로** 업로드해야 한다 — 인원이 늘수록 업로드가 (인원−1)배로 늘어 폰과 학교 와이파이가 못 버틴다. 이 한계를 직접 재서 확인했다.

**[핵심 기술 ②-C] 2단계: 중계 서버(SFU) 방식으로 전환**
비유: **우체국**. 내 영상을 중계 서버에 딱 1번만 올리면, 서버가 복사해서 친구들에게 나눠준다. 몇 명이 있든 내 업로드는 항상 1개 — 그래서 반 전체 그리드가 가능해진다.

**[핵심 기술 ②-D] 3단계: 그 중계 서버를 우리가 직접 운영**
중계 서비스를 빌려 쓰는 데서 멈추지 않고, 같은 오픈소스 중계 서버(LiveKit)를 **클라우드 컴퓨터에 우리 손으로 직접 설치·운영**했다 — 암호화 연결(HTTPS), 방화벽, 자동 재시작 설정까지.
**[말하기]** "직접 만들어 한계를 재고 → 구조를 갈아타고 → 그 서버를 직접 운영하는 데까지 갔습니다."

**[핵심 기술 ②-E] 영상은 저장되지 않는다**
그리드 영상은 실시간으로 **중계만** 되고 어디에도 녹화·저장되지 않는다. 서버 DB에 있는 건 공부 시간 숫자와 닉네임뿐.

### 핵심 기술 한 장 요약 (슬라이드용)

| 기술 | 하는 일 | 한 줄 비유 |
|---|---|---|
| MediaPipe (AI) | 몸·얼굴에 좌표 점 찍기 | AI는 점만, 판단은 우리 수학 |
| 캘리브레이션 | 나만의 자세 기준 만들기 | 체중계 영점 조절 |
| 홍채 닮음비 | 얼굴-카메라 거리 재기 | 수학 닮음비로 거리 역산 |
| 신호 8종 + 필터 | 오판 줄이기 | 증거 8개를 모아 판결 |
| WebRTC | 브라우저끼리 실시간 영상 | 줌이 쓰는 표준 |
| SFU (LiveKit) | 여러 명 영상 중계 | 우체국 — 1번 보내면 알아서 배달 |
| 온디바이스 분석 | 프라이버시 보호 | 영상은 내 폰 밖으로 안 나감 |

**[말하기]** ★라이브 시연 순서: 공부 시작 → 기준 등록 → 일부러 거북목 → 요정 반응·알림 → (폰 2대) 그리드 열기 → 콕 찌르기.

**★시연 준비 (중요)**: 시연 폰은 주소 뒤에 `?lkself=1`을 붙여 접속한다 — 영상이 **우리가 직접 운영하는 SFU**를 지나가게 되어, "셀프호스팅으로 구현했다"는 발표 설명과 실물이 일치한다. 시연 전 폰 2대로 그리드 접속을 미리 확인할 것(학교 와이파이가 UDP를 막으면 TCP 폴백으로 붙는지까지).

## 3. 현재 개발 진행 상태

**전부 배포 완료, 실제 서비스 중** — https://posture-guard-rust.vercel.app

| 영역 | 상태 |
|---|---|
| 자세 엔진 (신호 8종 + 개인화 기준 + 논문 반영) | ✅ 완료 |
| 공부 타이머 (순공·과목·목표·D-Day) | ✅ 완료 |
| 요정 (모션 9종 × 스킨 10종, 부위별 반응) | ✅ 완료 |
| 그룹 (랭킹·실시간 그리드·콕) | ✅ 완료 |
| 계정·동기화 (이메일/구글, 멀티기기) | ✅ 완료 |
| 통계 (캘린더·차트·리포트·온보딩) | ✅ 완료 |
| QC 실사용 피드백 반영 (온보딩·안내 개선) | ✅ 1차 완료 |

**숫자로 보는 개발량**: 커밋 93개 · 프론트 코드 약 5,000줄 · React 컴포넌트 25개 · 설계 문서 17편 · 자동 테스트 45개(전부 통과)

**기술 아키텍처 (엔지니어링 포인트)**:
- 프론트: React PWA (Vercel 배포) / 백엔드: **도커 컨테이너 5종을 GCP 클라우드 서버에서 직접 운영** — nginx 게이트웨이(HTTPS·접속 제한) + Express API + PostgreSQL + **Redis 캐시**(실시간 접속 상태·랭킹) + LiveKit SFU. 참고 논문이 제안만 했던 "Redis 통계 캐시" 구조를 실제로 구현.
- **실시간 3단 진화 서사**: ① WebRTC P2P 연결을 시그널링 서버까지 직접 구현 → ② 업링크 N-1 구조 한계를 확인하고 SFU(중계 서버) 아키텍처로 전환 → ③ 같은 오픈소스 SFU(LiveKit)를 **우리 서버에 직접 설치·운영**까지. (다이어그램: docs/시스템-아키텍처.md)
- 선행 학술논문과 대조 분석해 판정 로직 개선 — 논문의 실패 데이터(정면 카메라 한계)에서 배워 깊이(Z)·홍채 신호로 보완.

**[말하기]** "기능만 만든 게 아니라, P2P를 직접 구현해보고 한계를 재서 아키텍처를 갈아탔고, 그 중계 서버를 오픈소스로 직접 운영하는 데까지 갔습니다."

## 4. 향후 개발 계획

**단기 (2주 내, P1 — 기획서 완료 상태)**
1. **하루 타임라인 플래너** — 몇 시에 뭘 공부했고 언제 자세가 무너졌는지 한눈에 (열품타 플래너 + 자세 오버레이 = 유일무이)
2. **리포트 공유 카드** — 오늘 기록을 이미지로 만들어 인스타 인증 ("공스타그램" 바이럴 훅, **디자인·운영은 비개발 팀원 주도**)
3. 과목 기록 서버 동기화 · 그룹 목표시간 · 데이오프(쉬어도 스트릭 유지) · 전체 주간 랭킹

**검증 (M3 — 팀 미션)**
- 팀원 8명 실사용 데이터 수집 → 오탐률 측정 → 임계값 튜닝 (QC 체크리스트 운영 중)
- 거북목 깊이 신호 실기기 부호 검증, 새 홍채 신호 체감 평가

**중장기 (P2 비전)**
- 요정 진화(누적 공부시간에 따라 성장), 학년별 전국 랭킹, 주간 자세 챌린지 운영
- 사용자가 늘면: 관리형 DB 이전, 휴식 스트레칭 콘텐츠(자세 앱만의 휴식)

**[말하기]** "다음 단계는 기능 추가가 아니라 검증입니다 — 팀원 8명이 실제로 2주간 쓰면서 오탐률을 측정하고 조정합니다. 그리고 자세 데이터라는 우리만의 자산으로 '자세까지 보이는 플래너'를 완성합니다."

### 부록 — 예상 질문 대비
- **Q. 영상 유출 위험은?** → 영상은 기기 밖으로 안 나간다(온디바이스). 그리드 영상도 중계만 되고 저장되지 않으며, 서버·DB에는 숫자만 있다.
- **Q. 정확도는?** → 개인 기준 등록 + 신호 8종 교차 + 선행논문 임계값. 남은 오탐은 M3 실사용 데이터로 튜닝 예정이라고 솔직하게.
- **Q. 열품타와 뭐가 다른가?** → 측정이 더 정직하고(착석 기반), 자세 데이터가 있다. "과목별 자세 리포트"는 우리만 가능.
- **Q. 비용은?** → 정적 호스팅 무료 + 소형 VM — 학생 예산으로 운영 가능한 구조.
