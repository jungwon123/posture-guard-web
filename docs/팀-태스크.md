# 팀 태스크 배분 (8명)

> 원칙: 한 사람당 **지금 바로 시작할 태스크 2~3개 + 발표 전까지 낼 산출물**을 명시한다.
> 겹치는 희망(UX+QA 2명, 디자이너 2명, 발표 4명)은 페어·파트 분담으로 정리했다.
> 참고 문서: 기획서(docs/기획서.md), 브레인스토밍 가이드(docs/브레인스토밍-가이드.md)

---

## 조인성 — 총괄 PM · 발표 총괄

| # | 태스크 | 산출물 | 기한 |
|---|---|---|---|
| 1 | 주간 회의 운영: 매주 1회, 안건은 회의 전날까지 공지 | 회의록 (누가·무엇을·언제까지 3줄 형식) | 매주 |
| 2 | 브레인스토밍 세션 **진행자** (가이드 문서 그대로 진행, 60분) | 투표 결과 + 구체화 카드 3장 | 세션 당일 |
| 3 | 백로그 관리: 구체화 카드 3장을 우선순위 매겨 등록, 개발자와 난이도 조율 | 백로그 표 (기능/우선순위/난이도/상태) | 세션 후 3일 |
| 4 | 발표 파트 배분표 관리 (아래 "발표 구성" 표) + 리허설 일정 잡기 | 발표 순서표, 리허설 2회 | 발표 1주 전 |
| 5 | 활동 아카이브: 회의록·브레인스토밍 결과·테스트 결과를 한 폴더에 정리 + 최종 보고서 뼈대 (기획서 목차 재활용) | 팀 문서 폴더, 보고서 초안 | 상시 / 발표 1주 전 |

## 표수연 — UX 리서처(리드) · QA(서브) ※조윤준과 페어

| # | 태스크 | 산출물 | 기한 |
|---|---|---|---|
| 1 | 사용성 테스트 설계: 처음 보는 사람에게 **설명 없이** 시키기 — "기준 등록까지 혼자 몇 분 걸리나, 어디서 막히나" | 테스트 절차서 1장 + 관찰 기록지 양식 | 1주차 |
| 2 | 테스트 진행 2회: 데스크톱 버전 1회 + 웹 버전 1회 (각 3명 이상, 조윤준과 함께) | 관찰 기록 + "막힌 지점 TOP 5" | 2주차 |
| 3 | 결과를 개선 요구로 변환: "버튼이 안 보임" → "시작 버튼을 크게" 식으로 | 개선 요구 목록 (PM 백로그로 전달) | 테스트 후 3일 |
| 4 | 사용자 가이드 1페이지: 처음 쓰는 사람용 (설치→기준 등록→미니 모드) — 테스트에서 나온 "막힌 지점" 반영 | 사용 설명서 (스크린샷 포함) | 3주차 |

## 조윤준 — QA 리드 · UX(서브) · 발표(데모 시연) ※표수연과 페어

| # | 태스크 | 산출물 | 기한 |
|---|---|---|---|
| 1 | 기능별 테스트 케이스 작성: 기준 등록 / 알림 / 미니 모드 / PiP / 리플레이 — 각각 "이렇게 하면 → 이렇게 되어야 함" 3개씩 | 테스트 케이스 표 (약 15개) | 1주차 |
| 2 | 버그 리포트 양식 만들고 버그 보드 운영: 재현 방법 / 기대 / 실제 / 스크린샷 | 버그 보드 (발견→수정확인 상태 관리) | 상시 |
| 3 | 발표 **데모 시연** 담당: 시연 각본 작성 (일부러 거북목 → 알림 받기까지), 실패 대비 녹화 영상 백업 | 데모 각본 + 백업 영상 | 발표 1주 전 |

## 정세아 — 데이터 담당 · 테크니컬 발표

| # | 태스크 | 산출물 | 기한 |
|---|---|---|---|
| 1 | 데이터 수집 캠페인: 팀원 전원에게 녹화 방법(`r` 키) 안내 → 각자 "평소 공부 30분" 녹화 파일 걷기 | 녹화 JSON 8개 이상 | 1주차 |
| 2 | 리플레이 분석: 걷은 녹화를 리플레이로 돌려 전이 결과 정리 — 본인이 "그때 진짜 나쁜 자세였는지" 물어봐서 **오탐/미탐 카운트** | 정확도 표 (사람별 오탐·미탐) | 2주차 |
| 3 | 기준값 제안: 오탐 많으면 민감도 완화, 둔하면 강화 — 개발자와 함께 값 바꿔 재리플레이 | 튜닝 제안서 (전/후 비교) | 2주차 |
| 4 | 발표 **테크니컬 파트**: 동작 원리(기획서 5번) + 데이터 결과를 슬라이드 3~4장으로 | 발표 슬라이드 (원리·정확도) | 발표 1주 전 |

## 문권빈 — 리서처 · 디자이너 (발표물·브랜드) ※최윤우와 분담

| 2 | 브레인스토밍 보드 사전 세팅: 가이드 문서의 구역 6개를 Excalidraw에 그려두기 | 준비된 보드 링크 | 세션 전날 |

## 김규빈 — 도메인 리서처 · 발표(문제 정의 파트) ※이민엽과 페어

| # | 태스크 | 산출물 | 기한 |
|---|---|---|---|
| 1 | 거북목 근거 조사: 청소년 거북목 통계·건강 영향 — **출처가 분명한 자료 3개** (기사 말고 공공기관·논문 요약 우선) | 근거 요약 1장 (출처 링크 포함) | 1주차 |
| 2 | 설문 조사: 반 친구 20명+ — "하루 몇 시간 앉아 있나 / 목·어깨 아픈 적 / 이런 도구 쓸 의향" | 설문 결과 그래프 | 2주차 |
| 3 | 발표 **도입 파트**: 문제 정의(기획서 1번)를 설문·근거로 설득력 있게 | 발표 슬라이드 2~3장 | 발표 1주 전 |

## 이민엽 — 도메인 리서처 ※김규빈과 페어

조사 영역 분담: 김규빈 = **문제 쪽** (거북목 근거·설문), 이민엽 = **해결책 쪽** (세상의 비슷한 시도들).

| # | 태스크 | 산출물 | 기한 |
|---|---|---|---|
| 1 | 유사 서비스·시도 조사: 웹캠/AI로 자세를 감지하는 서비스·앱·연구 프로젝트 3개 이상 찾기 — 각각 "어떤 방식인가 / 영상은 어디로 가나(프라이버시) / 왜 우리가 다른가" | 유사 시도 비교표 (문권빈의 앱 체험기와 합침) | 1주차 |
| 2 | 설문 확대: 김규빈이 만든 설문을 다른 반·학년에도 돌려 표본 늘리기 (목표 40명+) | 설문 응답 (김규빈에게 전달) | 2주차 |
| 3 | "우리의 차별점" 한 장 정리: 조사 결과를 바탕으로 — 개인 기준 / 영상 무저장 / 지속 시간 판정 3가지를 남들과 비교 | 차별점 비교 1장 (발표 도입부 재료) | 2주차 |

> 테크니컬 라이터(문서 담당)는 공석 — 아래처럼 분산한다:
> **사용자 가이드** → 표수연 (사용성 테스트에서 나온 "막힌 지점"을 반영해 작성),
> **활동 아카이브·최종 보고서 뼈대** → 조인성 (회의록 관리의 연장).

## 첫 주에 당장 시작할 것 (요약)

- **조인성**: 첫 회의 소집 + 브레인스토밍 날짜 확정
- **문권빈**: Excalidraw 보드 세팅 (세션 전날까지)
- **표수연·조윤준**: 테스트 절차서·테스트 케이스 초안
- **정세아**: 녹화 수집 안내 공지
- **김규빈**: 근거 자료 3개 찾기 + 설문 문항 초안
- **최윤우**: 현재 화면 스크린샷 떠서 개선 포인트 메모
- **이민엽**: 유사 서비스(웹캠 자세 감지) 3개 조사 시작
