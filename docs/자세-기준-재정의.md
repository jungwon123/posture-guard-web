# 바른 자세 기준 재정의 (v2) — 거북목 정면 조준

> 목적: 정면 웹캠으로 신뢰성 있게 관측 가능한 축들에서 **거북목(전방머리)** 을 정면으로 겨누도록
> 신호 체계를 재정의한다. 중복(특히 `head_drop`)을 걷어내고, 지금까지 **간접 추정만 하던
> "머리 전방 이동"을 깊이(Z)로 직접 측정**한다.

## 0. 원칙

- **바른 자세 = 절대 인체 표준이 아니라 "내가 바르게 앉은 캘리브 기준 대비 얼마나 무너졌나".**
  개인 편차 기반이라 사람마다 다른 체형·카메라 위치에 강건하다.
- 정면 카메라가 **약한 축**(시상면 전방이동)은 worldLandmarks의 **깊이 Z** 와 얼굴 회전행렬로 보강한다.
- 신호는 **각자 다른 실패 유형 하나**를 겨눈다(중복 최소화). 겹치면 이중 감점 → 판정 편향.

## 1. 나쁜 자세의 5대 유형 (인간공학)

| # | 유형 | 시각적 신호 | 정면 카메라 관측성 |
|---|---|---|---|
| A | **거북목 / 전방머리** (forward head) | 귀가 어깨보다 **앞으로** 이동 | 🔴 약함(깊이 필요) → Z로 해결 |
| B | **고개 숙임** (목 굴곡) | 머리 pitch 아래로, 턱→가슴 | 🟡 얼굴 회전행렬로 실측 |
| C | **어깨 말림 / 굽은 등** | 어깨가 앞으로 말리며 어깨너비 축소 | 🟡 |
| D | **화면에 바짝** (거리) | 얼굴이 커짐 | 🟢 |
| E | **좌우 기울기 / 비대칭** | 어깨선이 한쪽으로 기욺 | 🟢 |

> A가 앱의 존재 이유(거북목)인데 **지금 직접 측정하는 신호가 없다.** 이번 재정의의 핵심.

## 2. 현재 신호의 문제 (v1)

| 신호 | 측정식 | 문제 |
|---|---|---|
| `proximity` | `earDist` (2D) | 양호 (D) |
| `pitch` | `(nose.y − earMidY)/earDist` (2D) | B의 2D 근사 — 얼굴 실측 `headPitch`가 더 정확 |
| `head_drop` | `(shMidY − nose.y)/shWidth` (2D) | **코 기반 → 고개 숙이면 같이 나빠짐 = `pitch`와 이중계산.** 폐기 대상 |
| `shoulder_roll` | `shWidth / earDist` (2D) | 약하지만 C를 겨눔 (유지) |

절대 레이어(posture3d.js, 프론트 전용):
- `headVertical = (shMidY − earMidY)/shoulderWidth` (world) — **귀 기반**이라 `head_drop`의 깔끔한 대체(머리 가라앉음).
- `shoulderTilt` (deg) — E.
- `headPitch` (deg, 얼굴 행렬) — B 실측.

핵심: **`head_drop`(코) 가 하려던 일을 `headVertical`(귀)+`headPitch`(실측)가 더 정확히 한다 → 폐기.**

## 3. 새 신호 세트 (v2) — 6개, 각자 다른 축

| # | 신호 | 겨냥 | 측정식 | 소스 | 나쁨 방향 | 기준 |
|---|---|---|---|---|---|---|
| 1 | **headForward** 🆕 | A 거북목 | `(shMidZ − earMidZ)/shoulderWidth` | world **Z** | 전방(귀가 카메라쪽) | `absRef.headForward` |
| 2 | **headPitch** | B 고개숙임 | 얼굴 행렬 pitch(deg) | face matrix | 기준 ±15° 초과 | `absRef.headPitch` |
| 3 | **headVertical** | A/B 머리 가라앉음 | `(shMidY − earMidY)/shoulderWidth` | world Y | 감소 | `absRef.headVertical` |
| 4 | **proximity** | D 거리 | `earDist` z-score | 2D | 증가 | `mu/sigma` |
| 5 | **shoulderTilt** | E 좌우기울기 | 어깨선 각도(deg) | world | 기준 +8° | `absRef.shoulderTilt` |
| 6 | **shoulderRoll** | C 어깨말림 | `shWidth/earDist` z-score | 2D | 감소 | `mu/sigma` |

- **폐기**: `head_drop`.
- **강등**: 2D `pitch` → 얼굴 미검출 시 `headVertical` 보조로만(핵심은 `headPitch`).
- **1·3 관계**: headForward(Z, 전방이동) 와 headVertical(Y, 수직하강)은 **다른 축**(거북목은 보통 둘 다 나타나지만 독립적으로 발생 가능) → 둘 다 유지하되 forward에 더 큰 가중치.

### headForward 부호 주의
world Z는 단일 카메라 추정치라 부호 규약이 흔들릴 수 있다. **캘리브 시 바른 자세의 기준값을 잡고, 그 기준에서 "전방" 방향으로 벗어난 편차만** deadzone 넘으면 감점한다(뒤로 젖힘은 감점 안 함, 비대칭). Z 노이즈 대응: One-Euro 강하게 + shoulderWidth 정규화(스케일 불변) + 넉넉한 deadzone.

## 4. 스코어링 아키텍처 (R1 — 진화형, 파리티 리스크 최소)

**관측 성격에 따라 신호를 둘로 나눈다:**

- **상대(z-score) 코어** = `{ proximity, shoulderRoll }`
  스케일·카메라 의존적이라 개인 평균/표준편차 기준이 자연스러움. 기존 `core.js` z-score 엔진 재사용.
- **절대(캘리브 기준) 게이트** = `{ headForward, headPitch, headVertical, shoulderTilt }`
  각도·기하 오프셋이라 "바른 자세 절대 기준 대비 편차"로 판정. `posture3d.js` 절대 레이어 확장.

```
score = coreZScore(proximity, shoulderRoll)  →  0~100
      × exp( − absPenalty(headForward, headPitch, headVertical, shoulderTilt) )
```

가중치(초안, 실측 후 튜닝):
- `ABS_W = { forward: 1.8, pitch: 1.2, vertical: 0.9, tilt: 0.5 }` (forward 최상 = 거북목 본질)
- core `WEIGHTS = { proximity: 0.6, shoulder_roll: 0.4 }` (pitch·head_drop 제거 후 재정규화)

### 왜 R1인가
- **`frontend/src/core.js`는 이미 파이썬과 분리된 fork** (파리티 대상은 옛 `web/js/core.js`) →
  **재설계를 프론트만으로** 할 수 있다. 파이썬/웹-js는 v1 레퍼런스로 두거나 나중에 맞춘다.
- 코어 변경면이 최소(head_drop·pitch 제거 + 가중치)이고, 신규 로직은 전부 절대 레이어에 격리.

## 5. 캘리브레이션 변경 (5초 "바른자세 기준 등록")

동시에 수집:
- core `mu/sigma` ← `{ proximity, shoulderRoll }` (기존 4→2 신호)
- `absRef` ← `{ headForward, headPitch, headVertical, shoulderTilt }` (headForward 추가)

`extractAbsolute()`에 headForward 추가, `finishAbsRef()`가 median으로 기준 확정.
기존 사용자: 재캘리브해야 headForward 기준 생김(없으면 해당 게이트 auto-skip = 무해).

## 6. 구현 단계 (프론트 전용)

1. **posture3d.js**: `extractAbsolute`에 `headForward` 추가 + `absPenalty/absWorst`에 forward 항 + `ABS_W` 재설정. One-Euro에 forward 채널.
2. **core.js(frontend fork)**: `WEIGHTS`에서 `pitch/head_drop` 제거 → `{proximity, shoulder_roll}` 재정규화. `extractSignals`는 유지(값은 계산하되 미사용 신호는 스코어에서 빠짐) 또는 정리.
3. **app.js**: 캘리브에서 headForward 샘플 수집, absRef에 저장, 블렌딩식에 forward 반영. 트래킹/Buddy worst에 "거북목(전방)" 반영.
4. **UI 라벨**: `SIGNAL_KR`에 전방머리 추가, head_drop 라벨 제거.
5. **검증**: posture3d 단위테스트(합성 world 랜드마크로 forward 부호·정규화·게이트), 빌드, 합성 포즈 렌더, **실기기 거북목 검증**.

## 7. 검증 계획

- **단위**: 정면 정자세(forward≈0 감점0), 목 앞으로(귀 Z가 어깨보다 카메라쪽 → forward 감점), 뒤로 젖힘(감점0=비대칭 확인), 노이즈 강건(One-Euro).
- **패리티**: frontend fork라 별도 파리티 없음 — 프론트 단위테스트로 대체. web/js·python은 v1로 보존.
- **실측**: 실기기에서 바른자세→거북목 전환 시 forward 신호가 반응하는지, 오탐(정상인데 감점) 없는지.

## 8. 열린 질문

- headForward 노이즈가 실기기에서 실용적인가? (안 되면 게이트 가중치↓ 또는 headVertical+proximity 조합으로 폴백)
- 2D `pitch`를 완전 제거 vs 얼굴 미검출 폴백으로 남길지.
- 정상 범위 deadzone/margin 실측 튜닝값.
