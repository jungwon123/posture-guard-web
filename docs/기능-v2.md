# 기능 v2 설계 — 브레인스토밍 반영

> 출처: 팀 브레인스토밍 (알림 선택 / 계속 쓰게 만들기 / 같이 쓰기)
> 원칙: **판정 코어(core.js·posture_guard.py)는 건드리지 않는다** — v2는 전부 "개입·보상" 계층 위에 얹는다.

## 우선순위

| 순위 | 기능 | 구현 |
|---|---|---|
| P0 | 알림 설정 (방식·멜로디·**내 노래 업로드**·세기) | 웹에 지금 구현 |
| P0 | 포인트 + 출석체크 (바른자세 → 적립, 표수연 아이디어) | 웹에 지금 구현 |
| P0 | 오늘 하루 리포트 | 웹에 지금 구현 |
| P0 | 척추요정 캐릭터 (BAD 지속될수록 화남) | 웹에 지금 구현 |
| P1 | 상점 (포인트 사용처: 요정 스킨·테마 색) | 최소 버전만 지금 구현 |
| P2 | 그룹 (열품타식 — 같이 쓰기) | **서버·계정 필요 → 설계만, 다음 단계** |
| 보류 | 게임, 화면 커스텀 전체 | 브레인스토밍 구체화 카드로 재정의 필요 |

## 1. 알림 설정 (P0)

| 항목 | 설계 |
|---|---|
| 방식 | 소리 / 진동 / 둘 다 / 무음(배너만) — 진동은 **안드로이드 크롬만** 동작(iOS·데스크톱 미지원)하므로 UI에 명시 |
| 멜로디 | 프리셋 4종 (딩동 / 차임 / 뾰로롱 / 경보) — WebAudio 음표 시퀀스로 내장, 파일 없음 |
| **내 노래** | 오디오 파일 업로드 (2MB 이하) → 브라우저 안에 저장(localStorage) → 알림 때 재생. 서버 업로드 아님 |
| 세기/횟수 | 음량 슬라이더 0~100% / 진동은 **횟수(1~3회)** — 웹은 진동 강도 제어가 불가해 횟수로 통일. 안드로이드=진동 펄스 반복, 아이폰=알림 재발송(renotify)으로 유도 |
| 에스컬레이션 | 1단계(BAD 진입) = 선택한 소리 1회 · 2단계(60초 지속) = 같은 소리 반복 + 진동 강 |
| 테스트 | "알림 테스트" 버튼 — 설정 즉시 확인 |

## 2. 포인트·출석 (P0)

- **적립**: GOOD 상태 **1분당 +1P** (BAD·AWAY 중엔 적립 정지. 차감은 없음 — 벌점은 금방 지치게 한다)
- **출석**: 하루 첫 감지 시작 시 **+10P**
- **표시**: 헤더에 `🪙 128P` 상시 표시, 적립 순간 +1 애니메이션
- 저장: 전부 localStorage (`pg_points`, `pg_attend_last`) — 서버 없음

## 3. 척추요정 캐릭터 (P0) ✅ 스프라이트 9상태 적용됨

서비스 이름이자 마스코트 = **척추요정**. 상태가 나빠질수록 단계적으로 반응한다 (전이: 주의 alert → 무너짐 hurt_부위 → 방치 angry → 심각 hurt_부위 / 교정 encourage / 성공 praise / 보상 reward / 평상시 가끔 encourage). 헤더·미니 모드(PiP)·얼굴커버·Buddy(돌아다니는 요정)·리포트·알림 문구에 등장.
에셋: `web/assets/fairy/` — 아틀라스 9상태×4프레임 + GIF 9종 (출처: ~/Downloads/export, cheokcheok 스프라이트 파이프라인). 구매 스킨(고양이·곰)은 이모지.

| 상황 | 스프라이트 모션 | 알림/문구 |
|---|---|---|
| 기준 등록 전 / AWAY | idle (흐리게) | — |
| 기준 등록 중 (5초) | encourage | "곧게 펴볼까요?" 응원하며 대기 |
| GOOD | idle | — |
| GOOD 지속 (3분마다 4초) | encourage | 평상시 가끔 응원 — 소리·알림 없음 |
| 점수 하락 중 (BAD 후보) | encourage | — (아직 알림 없음, 다잡기 응원) |
| CAUTION (주의) | alert | 말풍선 "살짝 무너졌어요" — 알람·진동 없음 |
| BAD 진입 | **원인별 아픔** hurt_neck/back/pelvis | "자세가 틀어졌어요! 허리를 펴요" |
| BAD 20초+ (에스컬레이션) | angry | "교정 안 했어?! ○○초째 나쁜 자세예요" |
| BAD 60초+ (방치·비네트) | 원인별 아픔 hurt_neck/back/pelvis | 아픔 절정 — 방치의 결과를 보여줌 |
| BAD에서 고치는 중 (GOOD 후보) | encourage | — |
| 복귀 (BAD→GOOD) | praise (3초) | "정말 잘하고 있어요! 포인트 다시 적립" |
| 복귀 (CAUTION→GOOD) | praise (2.5초) | 모션만 — 소리·알림 없음 |
| 포인트 적립·출석·상점 구매 | reward (2.5초) | "보상 받았어요!" |
| 오늘 리포트 | 90%+ praise / 70%+ idle / 미만 hurt_neck | 등급별 캐릭터 표시 (일 단위라 원인 구분 없음) |

**원인(worst) 신호 → 아픔 부위 모션** — `frontend/src/reward.js`의 `HURT_MOTION`이 SSoT. 헤더 요정·미니(PiP)·얼굴커버·Buddy가 전부 이 매핑을 공유해 말풍선 멘트와 아픈 부위가 항상 일치한다. BAD 중 worst가 잘게 바뀌어도 아픔 모션은 최소 4초 유지(래치, `app.js HURT_HOLD_SECS`).

| 계열 | 원인 신호 (worst 키) | 모션 |
|---|---|---|
| 머리·목 | head_drop (머리 가라앉음·거북목 전방이동), pitch (고개 숙임), proximity (화면 근접) | hurt_neck |
| 어깨·등 | shoulder_roll (어깨 말림·span 축소), shoulder_tilt (어깨 높이 기울기) | hurt_back |
| 삐딱함 | head_tilt (좌우 쏠림·갸웃), hand_face (턱괴기) | hurt_pelvis |

## 4. 오늘 하루 리포트 (P0)

"리포트" 버튼 → 카드 표시. 데이터는 이미 쌓이는 상태 전이 기록에서 계산.

- 총 감시 시간 / **바른 자세 비율(%)** / 나쁜 자세 횟수·총 시간 / **최장 연속 바른 자세** / 오늘 얻은 포인트
- 한 줄 평가: 비율 90%+ "완벽!" · 70%+ "좋아요" · 그 미만 "내일은 요정을 웃게 해줘요"

## 5. 상점 (P1 — 최소 버전)

포인트 사용처가 없으면 포인트가 죽는다. 최소 2종만:

| 상품 | 가격 | 효과 |
|---|---|---|
| 요정 스킨: 고양이(🐱/😾) | 30P | 캐릭터 이모지 세트 교체 |
| 요정 스킨: 곰(🐻/🐻‍❄️) | 30P | 〃 |
| 포인트 테마(초록→보라 등 액센트 색 2종) | 20P | 화면 강조색 변경 |

구매 내역: `pg_shop` (localStorage). 환불 없음, 스킨은 언제든 갈아끼기 가능.

## 6. 그룹 — 같이 쓰기 (P2, 설계만)

열품타처럼: 그룹 코드 만들기/가입 → 이번 주 "바른 자세 시간" 랭킹 보드.

- **필요한 것**: 서버 + 계정 + DB (지금 웹 버전은 서버가 없음) → 다음 단계 과제
- 공유하는 데이터는 **집계 숫자뿐** (GOOD 누적 분·포인트). 영상·신호는 절대 서버로 안 감 — 프라이버시 불변식 유지
- 최소 설계: 그룹 코드 6자리, 주간 리더보드 1개, 익명 닉네임. 그 이상(채팅 등)은 안 함

## 7. 눈 깜빡임 챙기기 (베타) ✅ 구현됨

자세 말고 눈도 지켜주는 확장 (브레인스토밍 "눈 깜빡임" 아이디어). 화면을 오래 보면 깜빡임이 분당 15~20회 → 5~7회로 떨어져 눈이 건조해진다.

- **방식**: 얼굴 모델(MediaPipe Face Landmarker)의 눈 감김 점수로 깜빡임(상승 에지)을 카운트 → 분당 횟수 추정. 분당 8회 미만이면 "눈 깜빡이세요" 알림
- **주기 샘플링** (배터리 절약 핵심): 계속이 아니라 **3분마다 30초씩만** 얼굴 모델을 돌린다. 자세용 Pose 모델과 별개라 켤 때만 로드
- **선택 토글**: 알림 설정 아래 "눈 깜빡임 챙기기" 체크박스. 헤더에 `👁 N회/분` 표시
- 튜닝 상수: `BLINK_WINDOW_SEC=30`, `BLINK_INTERVAL_SEC=180`, `BLINK_LOW_RATE=8` (`web/js/app.js`)
- 성능: 데스크톱·최신 태블릿 여유. 저사양 폰은 주기 샘플링으로 부담 최소화

| 키 | 내용 |

| `pg_profile` | 캘리브레이션 기준 (기존) |
